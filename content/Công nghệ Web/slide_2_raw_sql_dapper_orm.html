Hành Trình Kết Nối Database:
Raw SQL, Dapper & Full ORM

Từ câu lệnh SQL thuần thô sơ đến các Micro-ORM và Full ORM hiện đại.

01. Raw SQL Cấp độ nền tảng

Viết chuỗi câu lệnh SQL trực tiếp và tự đọc từng cột dữ liệu. Kiểm soát 100% hiệu năng nhưng dài dòng, dễ dính lỗi bảo mật nếu cộng chuỗi.

Hiệu năng: 100% Độ an toàn: Thấp (Thủ công)

02. Dapper Micro-ORM

Vẫn viết SQL chủ động nhưng tự động hóa hoàn toàn khâu Mapping (ánh xạ dữ liệu vào Object) và tham số hóa chống SQL Injection.

Hiệu năng: ~98% Mã nguồn: Gọn nhẹ

03. Full ORM EF Core / Prisma

Thao tác 100% bằng đối tượng OOP và LINQ/Method. Hệ thống tự động sinh câu lệnh SQL, quản lý trạng thái và Migration.

Tốc độ code: Rất nhanh Kiểm soát SQL: Trung bình

1. Khái Niệm Mapping (Ánh Xạ Dữ Liệu)

Cầu nối dịch dữ liệu giữa Thế giới Bảng Quan hệ (Relational DB) và Thế giới Đối tượng (OOP).

Thế giới Database (Bảng users) Rows & Columns

Lưu trữ dạng bảng phẳng, kiểu dữ liệu SQL (INT, VARCHAR, DECIMAL) và tên cột thường viết kiểu snake_case.

id (INT PK) 101
full_name (VARCHAR) 'Nguyễn Thành Long'
wallet_balance (DECIMAL) 2500000.00

Thế giới Ứng dụng (Class User) Objects & Properties

Lưu trữ trên RAM dưới dạng Object hướng đối tượng, kiểu dữ liệu ngôn ngữ (int, string, decimal) và đặt tên PascalCase.

public int Id { get; set; } 101
public string FullName { get; set; } "Nguyễn Thành Long"
public decimal WalletBalance { get; set; } 2500000m

Bài toán Mapping: Làm sao chuyển hàng nghìn dòng kết quả từ DataReader sang danh sách List<User> mà không phải gõ tay từng dòng user.Id = reader.GetInt32(0)?

2. Cấp Độ 1: Raw SQL (ADO.NET / Driver Thuần)

Kiểm soát tối đa nhưng tốn công sức ánh xạ thủ công và tiềm ẩn rủi ro nối chuỗi.

Code đọc & ánh xạ thủ công Dài dòng

// 1. Dễ dính SQL Injection nếu cộng chuỗi trực tiếp: string sql = "SELECT id, full_name FROM users WHERE id = " + inputId; using var cmd = new NpgsqlCommand(sql, conn); using var reader = cmd.ExecuteReader(); // 2. Phải tự gán từng cột bằng tay (Manual Mapping): if (reader.Read()) { return new User { Id = reader.GetInt32(0), FullName = reader.GetString(1) }; }

Đánh giá Raw SQL

  • Ưu điểm: Tốc độ thực thi nhanh nhất (không có chi phí trung gian), tối ưu được các câu truy vấn báo cáo cực kỳ phức tạp.
  • Nhược điểm 1 (Boilerplate): Bảng có 30 cột phải viết 30 dòng reader.Get.... Đổi tên cột dễ gây lỗi lúc chạy (Runtime Error).
  • Nhược điểm 2 (Bảo mật): Lập trình viên quên dùng Parameters.AddWithValue mà cộng chuỗi trực tiếp sẽ mở toang cửa cho SQL Injection.

3. Cấp Độ 2: Dapper (Micro-ORM)

Điểm cân bằng vàng: Giữ nguyên sức mạnh chủ động của SQL, tự động hóa hoàn toàn khâu Mapping.

Truy vấn với Dapper trong C# Gọn & An toàn

string sql = @" SELECT id AS Id, full_name AS FullName, wallet_balance AS WalletBalance FROM users WHERE id = @UserId"; // Tự động truyền tham số an toàn + Tự động ánh xạ ra Object User var user = await conn.QueryFirstOrDefaultAsync<User>( sql, new { UserId = 101 } );

Cơ chế hoạt động bên dưới của Dapper

  • Parameterized Query tự động: Object new { UserId = 101 } được tự động biến thành DbParameter, triệt tiêu nguy cơ SQL Injection.
  • IL Emit Caching: Lần đầu chạy, Dapper sinh mã máy (IL Code) để map cột sang thuộc tính Class và lưu vào Cache. Các lần sau nhanh gần ngang code tay ADO.NET.
  • Phù hợp khi: Hệ thống cần hiệu năng cao, cấu trúc 3-Tier (DAO / BUS / Controller) rõ ràng và lập trình viên vững SQL.

4. Cấp Độ 3: Full ORM (Entity Framework Core / Prisma)

Tự động hóa toàn diện từ viết truy vấn, theo dõi thay đổi (Change Tracking) đến quản lý Migration.

Thao tác bằng LINQ / OOP 100% Trừu tượng cao

// Không cần viết chữ SQL nào, trình dịch tự sinh câu lệnh var user = await dbContext.Users .Include(u => u.Orders) .FirstOrDefaultAsync(u => u.Id == 101); // Change Tracker tự phát hiện thuộc tính thay đổi để sinh lệnh UPDATE user.WalletBalance += 500000m; await dbContext.SaveChangesAsync();

Lợi ích & Cạm bẫy cần lưu ý

  • Lợi ích lớn: Phát triển tính năng CRUD cực nhanh, kiểm tra lỗi kiểu dữ liệu ngay lúc biên dịch (Compile-time), hỗ trợ Code-First Migration.
  • Chi phí Change Tracking: Tốn thêm RAM và CPU để theo dõi trạng thái từng Object (nên dùng .AsNoTracking() khi chỉ đọc).
  • Lỗi N+1 Query & Câu SQL kém tối ưu: Nếu lạm dụng vòng lặp hoặc Include quá nhiều bảng, ORM có thể sinh ra câu lệnh JOIN khổng lồ làm chậm DB.
