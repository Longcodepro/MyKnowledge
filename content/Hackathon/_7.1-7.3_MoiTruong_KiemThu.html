7.1–3

Môi trường, mã nguồn, kiểm thử

Công cụ dùng để làm, cấu trúc thư mục repo và kế hoạch kiểm thử với 16 ca chức năng chính.

  • Backend Python 3.11 + FastAPI; frontend React + TypeScript (Vite); hạ tầng cục bộ Docker Compose.
  • Thuật toán, máy trạng thái, API đều có kiểm thử; tác tử AI kiểm thử bằng LLM giả (mock) trả JSON cố định.
  • Bảng 7.2 có 16 test case (TC01 đến TC16) phủ các Use Case chính.

7.3.1 Kiểm thử đơn vị và tích hợp

  • Thuật toán: DAG (phát hiện chu trình, rút gọn bắc cầu), truy vết gốc, hàm trọng số và ghép cặp, thử với đồ thị dựng sẵn và kết quả biết trước.
  • Máy trạng thái MasteryRecord: mọi chuyển trạng thái hợp lệ và không hợp lệ (Bảng 4.8).
  • Tác tử AI: LLM giả trả JSON cố định để kiểm thử luồng; Guard thử bằng bộ câu tấn công ở Phụ lục B.
  • API: kiểm thử phân quyền theo vai trò và theo lớp (NFR-08).

7.3.2 Test case chức năng (Bảng 7.2)


Dễ bị hỏi

Vì sao kiểm thử AI bằng LLM giả (mock)?

LLM thật cho kết quả không cố định và tốn tiền. Mock trả JSON cố định nên kiểm thử được luồng (Guard, Judge, Tutee, lưu điểm) lặp lại giống nhau mỗi lần chạy.

Kiểm thử Guard bằng gì?

Bộ câu tấn công ở Phụ lục B (jailbreak, dán lời giải…). Chỉ tiêu đo ở 7.4: chặn ≥ 90% và tỉ lệ Đạt sai là 0%.

Vì sao có TC16 (SV A xem kết quả SV B)?

Để chứng minh quyền sở hữu hoạt động: cùng vai trò sinh viên nhưng gọi API xem dữ liệu người khác phải trả 403 FORBIDDEN (NFR-08).

TC10 (điểm 82 nhưng vẫn FAILED) kiểm điều gì?

Quy tắc Đạt BR-03: ngoài điểm tổng phải đủ ý chính bắt buộc. Thiếu ý KP3 thì trượt dù điểm cao, và phản hồi chỉ gợi ý bằng câu hỏi, không nói đáp án.

TC11 đo gì?

Độ trễ của bản đồ nhiệt: 5 SV trượt N5 liên tiếp thì nút N5 phải chuyển đỏ trên dashboard trong vòng 3 giây.
