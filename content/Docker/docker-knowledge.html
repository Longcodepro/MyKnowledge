Docker là gì

Docker đóng gói ứng dụng cùng mọi thứ nó cần (hệ điều hành rút gọn, thư viện, cấu hình) vào một image, rồi chạy image đó thành container giống hệt nhau trên mọi máy. Nhờ vậy "chạy được trên máy tôi" cũng là "chạy được trên máy bạn và trên server".

Máy ảo (VM)Container
Hệ điều hànhMỗi VM có một hệ điều hành đầy đủDùng chung kernel (nhân) của máy chủ
Khởi độngChục giây đến vài phútThường dưới vài giây
Dung lượngHàng GBVài chục đến vài trăm MB
Cô lậpMạnh (phần cứng ảo hoá)Nhẹ hơn (cô lập ở mức tiến trình)

Trên Windows và macOS, Docker Desktop chạy một máy ảo Linux nhỏ bên trong, container thật sự chạy trong máy ảo đó. Trên Linux, Docker Engine chạy trực tiếp.

Các khái niệm cần thuộc

Khái niệmLà gì
ImageBản đóng gói chỉ đọc, dùng làm khuôn tạo container. Tải từ registry hoặc tự build.
ContainerMột bản đang chạy (hoặc đã dừng) tạo từ image. Xoá container thì dữ liệu ghi bên trong nó mất, trừ phần nằm trong volume.
VolumeNơi lưu dữ liệu nằm ngoài container, còn lại khi container bị xoá. Dùng cho database.
RegistryKho chứa image (Docker Hub là kho công cộng mặc định). postgres:16-alpine = tên image : tag (phiên bản).
DockerfileCông thức build một image: mỗi dòng là một lớp (layer), Docker dùng lại cache lớp nào không đổi.
Docker ComposeFile docker-compose.yml mô tả nhiều container chạy cùng nhau (service, cổng, biến môi trường, volume) để bật tất cả bằng một lệnh.
NetworkMạng ảo nối các container. Trong Compose, các service gọi nhau bằng tên service, không dùng localhost.
DaemonTiến trình nền dockerd làm mọi việc thật; lệnh docker chỉ là client gửi yêu cầu tới nó.

Sơ đồ 2: image gồm các lớp, container có lớp ghi riêng

Hai container tạo từ cùng một image dùng chung các lớp chỉ đọc, nên tốn rất ít chỗ. Mỗi container chỉ thêm một lớp ghi mỏng cho những gì nó thay đổi lúc chạy.

Sơ đồ 3: lệnh nào đưa image và container sang trạng thái nào

Với Compose: up = pull/build + run cho tất cả service, stop = stop, down = stop + rm. Dữ liệu trong volume không đổi theo các mũi tên này, chỉ mất khi docker rm -v, docker compose down -v hoặc docker volume rm.

Sơ đồ 4: các trạng thái của một container

Exited không phải lỗi: chỉ là container đã dừng (tự thoát hoặc bị stop). Mã thoát khác 0 thường là có lỗi, xem bằng docker logs.

Sơ đồ 8: lớp nào dùng cache, lớp nào chạy lại

Khi một lớp thay đổi, mọi lớp phía dưới nó phải chạy lại. Đó là lý do COPY package*.json nằm trước COPY . .: sửa code không làm mất cache của bước cài thư viện.

Sơ đồ 9: multi-stage build

Giai đoạn 1 cần cả công cụ build lẫn thư viện dev; giai đoạn 2 chỉ cần những gì để chạy. Kết quả là image cuối nhẹ và ít bề mặt tấn công hơn.

Lệnh build

LệnhLàm gì
docker build -t myapp:1.0 .Build với tên và tag; dấu . là thư mục ngữ cảnh (build context)
docker build -f Dockerfile.prod .Dùng Dockerfile khác tên
docker build --no-cache .Bỏ qua cache, build lại từ đầu
docker build --target build .Chỉ build tới giai đoạn có tên build
docker build --build-arg VERSION=2 .Truyền giá trị cho ARG
docker build --platform linux/amd64 .Build cho CPU khác (vd máy ARM build cho server x86)

Build context là toàn bộ thư mục bạn đưa vào lệnh build; Docker gửi nó cho daemon. Thư mục càng to, build càng chậm, nên luôn có .dockerignore.

Dockerfile mẫu: NestJS / Node (production, multi-stage)

FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
EXPOSE 4000
CMD ["node", "dist/main"]

Dockerfile mẫu: Next.js (chế độ dev)

FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
EXPOSE 3000
CMD ["npm", "run", "dev"]

Dockerfile mẫu: Python (FastAPI)

Sơ đồ 13: tách mạng để cô lập service

services:
  web: { networks: [front] }
  api: { networks: [front, back] }
  db:  { networks: [back] }
networks: { front: {}, back: {} }

Mặc định Compose cho mọi service chung một mạng nên đã gọi nhau được. Chỉ cần tách mạng khi muốn che bớt service (như database) khỏi các service không cần tới nó.

File docker-compose.yml (ví dụ BrewLite, rút gọn)

services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    ports:
      - "${DB_PORT}:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      retries: 10

  backend:
    build: ./backend
    ports:
      - "${BACKEND_PORT}:4000"
    depends_on:
      db:
        condition: service_healthy

volumes:
  pgdata:

10 quy tắc vàng

  1. Image là khuôn chỉ đọc, container là bản chạy từ khuôn; xoá container không mất image.
  2. Dữ liệu cần giữ phải nằm trong volume; không có volume thì xoá container là mất.
  3. down -v xoá luôn dữ liệu database: chỉ dùng khi thật sự muốn làm lại từ đầu.
  4. Sửa code thì --build; chỉ sửa .env thì --force-recreate.
  5. Trong container localhost là chính nó; gọi container khác bằng tên service.
  6. Cổng viết máy:container; phía trái dùng từ máy bạn, phía phải dùng giữa các container.
  7. Dòng ít đổi đặt trước trong Dockerfile để tận dụng cache.
  8. Không commit .env, chỉ commit .env.example.
  9. Container thoát ngay thì việc đầu tiên là docker logs.
  10. Ghim tag phiên bản (postgres:16-alpine), tránh latest khi cần ổn định.
